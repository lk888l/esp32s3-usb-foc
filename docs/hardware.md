### 20 kHz / 70% 零相钳位候选

源码默认 PWM 配置仍为 **10 kHz / 50%**。当前设备使用 `build/rated-current-20261104/bus.sdkconfig` 构建的 `pwm_profile:"20k70_experimental"`，不是默认配置已经改为 20 kHz。新调制在允许时将最低相钳为零，接近扇区边界时调整公共偏置；非零 PWM 指令脉宽仍保持至少 **4% duty，即 20 kHz 下 2 μs**，零相通过硬件强制 LOW，避免峰值比较事件产生窄脉冲。驱动器输出脉宽仍需示波器验证。遥测为 `pwm_duty_floor:0`、`pwm_min_active_duty:0.04`、`pwm_zero_clamp:true`。19.4 V 下可配置电压上限由原来的 `19.4 × 0.66 / √3 ≈ 7.3924 V` 提高为 `19.4 × 0.70 / √3 ≈ 7.8404 V`；这是调制能力，不是已验证的负载输出。[当前候选启动快照](../build/rated-current-20261104/20k-clamped-boot.json)

该候选以相邻 PWM 周期分别触发 ADC，三个 START 的名义相对时刻为 0 / 50 / 100 μs，两个有效相电流样本存在 **50 μs 时间差**。每槽检查低侧窗口，并拒绝两个有效采样之间跨越电压指令更新的组合；这些检查不能把非同时采样变成同时采样。电流纹波和动态过程中，第三相重建及 dq 变换仍可能受到时间差影响，需要保持点幅值比较和外部波形验证。

零相钳位版本已构建、烧录，并在 **0.08 A / 0.8 V 限制**下完成约 5 秒使能检查：109 份快照的目标均为 0，状态无故障，结束 idle；首末累计拒绝采样增加 **97**，有效控制次数增加 24652。它验证了所测零目标运行和停止行为，不能作为实际 0.08 A 或 0.8 A 跟踪证据。[零目标检查](../build/rated-current-20261104/20k-clamped-low-current.json)

最终复核又补充了逐相 force 更新的迟到保护：发生 force mask 变化前，以最新计数器检查距各变化相的新上升沿严格超过 5 μs；寄存器写入后再次检查，失败立即拉低 nSLEEP 并锁存跟踪失效，不能继续接受该组采样。最终已烧录镜像为 `experimental-20k70-force-guard.bin`，ELF SHA256 为 `2a81b6744247c657cbb50adc80bf26487e308c9c9aa985d4a9a6de3b7742fd4c`。重新执行约 5 秒零目标启停：108 份快照目标全为 0，拒绝增加 98、有效控制增加 24738，结束 idle / fault=none / duty=[0,0,0]、母线约 19.448 V；配置与校准恢复一致。14 组桌面测试全部通过。保护分支、扇区迁移及有载声音仍未用实机覆盖。[最终零目标启停记录](../build/rated-current-20261104/20k-force-guard-idle-enable.json)

### 保存、恢复与已保存参数

丢失采样突发后，`sampling_restart_required:true` 表示流水线已停止接受后续突发，须在停机状态显式 `clear` 重建采样硬件，恢复不会自动使能。另已修复 NVS 写入暂时阻塞回调后留下采样失步的问题：每次实际尝试保存结束后，无论写入成功与否，Console 都请求电机任务重建采样，并在共用 400 ms 期限内等待新完整 ADC 快照。内部重建不清除原有故障，不修改校准、不自动产生力矩。实机 fault 下保存的回复为 `ok:true`、`adc_sample_valid:true`、`adc_completed_mask:7`、`sampling_restart_required:false`，同时保留原 `adc_window_or_control_deadline` 故障，验证了采样恢复与故障确认分离。[故障状态保存后读回](../build/rated-current-20261104/save-fault-restart.json)

当前 NVS 保存的是：名义母线 **19.4 V**、电流上限 **0.8 A**、电压限制 **2.35 V**、Kp=0.4、Ki=200、mode=3（弹簧）、strength=20、endstop=20、damping=0.003、10° 档距；校准 direction=+1、7 极对、electrical_zero=**6.0791655 rad**。7.2 V 试验参数没有保存。当前候选启动快照及低限制检查结束均为 idle / fault=none，母线采样有效。绝对相电流、温升和噪声频谱/声压尚未通过外部仪器验证。

随后在 idle 状态再次保存，确认完整 ADC 快照恢复后，以 RAM 临时 0.08 A / 0.8 V 上限执行 USB 回归。分字节与 CRLF、四条流水请求、非法帧丢弃、100 次状态查询、20 次重连不自动使能，以及独立运行后显式停止均通过。最后恢复原参数，读回 idle / fault=none / duty=[0,0,0]，母线约 19.503 V，采样有效且无需重同步。这是协议及恢复验证，不是非零电流跟踪验证。[USB 回归](../build/rated-current-20261104/usb-20k-clamped.json)、[保存与最终状态](../build/rated-current-20261104/save-usb-final.json)

## 2026-11-04 新增母线电压采样

用户已将电源升至 **19.4 V**，并确认驱动板 **H1-10（0.1_VCC）接到 ESP32-S3 GPIO11**。新增固件通过 ADC2_CH0 读取分压信号，现场遥测约 **19.43–19.47 V**，与用户报告的电源电压接近。初次启动快照为 19.426 V、ADC 引脚 1766 mV，后续快照为 19.459 V、1769 mV；均为 `bus_voltage_valid:true`、`bus_voltage_error:0`。这些是板上 ADC 读数，尚未用驱动板端外部电压表完成精度标定。[初次读回](../build/rated-current-20261104/bus-first-boot.json)、[后续读回](../build/rated-current-20261104/primed-status.json)

已实际查看用户原理图 `\\nas\home\archive\docs\simple-foc\simple-foc-v2.0.jpeg`：分压上臂 R_DV1 为 **47 kΩ**，下臂 R_DV2 为 **4.7 kΩ**，因此 `Vbus = Vadc × 11`，不能按 `0.1_VCC` 丝印直接乘 10。19.4 V 对应引脚电压约 1.764 V；接入 GPIO11 的是这个分压点，母线 VM 不直接接 MCU。GPIO11 未与 PWM、电流采样、SSI 或 USB 接线重叠。DRV8316CT 本身采用硬件引脚配置；本次增加的是驱动模块分压信号的 ADC 读取。[TI DRV8316C 官方资料](https://www.ti.com/product/DRV8316C)

`CONFIG_KNOB_BUS_VOLTAGE_SENSE` 为接线后启用的编译选项，通用默认关闭；`CONFIG_KNOB_BUS_DIVIDER_MILLI` 默认 11000，表示倍率 11。ADC2 使用 12 位、12 dB 衰减及芯片 eFuse 曲线校准，在独立 core 0 任务中每 10 ms 读取一次。电流的 ADC1 数字控制器、扫描表和 GDMA 不因母线读取而追加通道。ESP32-S3 的 ADC 单元可以分别使用不同模式，oneshot 读取不放入 ISR；适配器依据本地 IDF 5.5.6 的 ADC2 RTC 控制路径实现。[ESP-IDF ADC oneshot 文档](https://docs.espressif.com/projects/esp-idf/en/v5.5.2/esp32s3/api-reference/peripherals/adc_oneshot.html)

开启采样后，调制使用有效的实测母线，并按实测值限制 PI 的可用电压。`config.bus_voltage` 仍保存名义配置、决定可配置电压上限，实测值不反写 NVS；因此早期快照中配置仍为 11.62 V，而顶层 `bus_voltage` 已为约 19.4 V，这是不同字段的含义。采样失败、ADC 饱和或换算值越出 4.5–30 V 时禁止使能；运行时锁存 `bus_voltage_invalid`，超过 100 ms 未得到可用新样本时锁存 `bus_voltage_stale`。开启采样后不会回退到手动配置值。停止后显式 `clear` 可请求无效母线监测器重新初始化，待新快照有效后才能再次显式 `enable`；电压恢复不会自动恢复力矩。

扩展诊断回复超过 4096 字节时，原先整段提交 USB TX 会受到驱动环形缓冲区单项大小限制。发送现改为每次最多 512 字节，保留部分写入处理和 JSON 正文共用的 100 ms 截止时间；线上仍是一条 LF 结束的 JSON，客户端 8192 字节行上限不变。详细字段和故障语义见[协议说明](protocol.md#2026-11-04-母线电压与发送更新)。

感测增益接法仍为已确认的 GAIN 接地、0.15 V/A。**相电流绝对尺度尚未经过外部仪器标定**；母线读数有效不能替代相电流标定、负载电流或温升验证。后续 PWM 配置及运行测试结果另行记录，以下此前实验保留原有条件和结论。

必须核实模块配置：

- MODE 为普通 3x PWM，SOx 有效；INLx 及 DRVOFF 必须由模块正确拉置。MODE 直接接 AVDD 的 3PWM+限流模式会禁用 SOx，不能用于这里的电流闭环。
- GAIN 的四种设置：AGND=0.15、悬空=0.3、47 kΩ 到 AVDD=0.6、AVDD=1.2 V/A。2026-11-04 用户补充确认 GAIN 直接接地，提供的 `\\nas\home\archive\docs\simple-foc\simple-foc-v2.0.jpeg` 原理图也显示 pin 36 接地，与当前 0.15 V/A 配置一致；尚未进行外部电流标定。
- SOx 的零点是 VREF/2，电流由 OUTx 流向电机时 SOx **升高**（TI Fig.8-30）。换算为 `(SOx - offset) / gain`；已加入极性回归测试。软件会在唤醒后全低侧状态测量三个零点，拒绝异常零点或过大噪声。
- 使用备用 AS5600 后端时，I²C 应有适合 400 kHz 的外部上拉；已启用芯片内部上拉作为辅助。
- nSLEEP 最好有板级下拉，保证上电至 GPIO 初始化之前也保持关闭。
- 本接线没有 nFAULT；只能读取现有信号，不能从 CT 版本读取 SPI 故障寄存器。不能把驱动器自身 8 A/16 A OCP 当作当前电机的额定电流保护。

## 2026-11-04 默认 MT6701 SSI 编码器

MT6701 使用 3.3 V 供电，与 ESP32-S3 和电机驱动共地。MODE 接 3.3 V，VDD 旁放置 100 nF 去耦；SOP-8 的 DO/CLK/CSN 分别为 6/7/8 脚，MODE 为 2 脚。参照手册 Fig.22/23 的 SSI 接线；模块的丝印可能仍写作 SDA/SCL/Z，应核对实际连线。CSN 必须由 GPIO10 独立驱动，不能固定在高电平。只有五个 I²C 接线端子的模块需要另行引出 CSN/Z，不能直接当作完整 SSI 模块接入。

SPI2 使用 GPIO12 CLK、GPIO13 MISO/DO、GPIO10 CSN，不使用 MOSI。默认 2 MHz、MSB 优先、mode 1（CPOL=0、CPHA=1），在上升沿由传感器更新、下降沿采样。**Rev.1.8 正文的 idle-high 描述与 Fig.24/25 波形有矛盾；本实现依据波形使用 mode 1。** CSN 在时钟前后各保持一个时钟周期的建立/保持时间。接线后的逻辑分析仪验证应确认一帧只有 24 个时钟，并核对 CRC 与转动方向。[MT6701 SSI 时序与参考接线](https://www.magntek.com.cn/upload/pdf/202407/MT6701_Rev.1.8.pdf)

驱动通过 ESP-IDF SPI master 的 DMA 接收完整 24 位：14 位角度、4 位 Mg 状态和 6 位 CRC。接收内存在内部 DMA 可访问 RAM 中按 4 字节对齐并预留 4 字节；线上仍只产生 24 位传输。没有命令、地址或 dummy 时钟。DO 启用内部上拉，使悬空输入倾向于读成会被 CRC 拒绝的全 1 帧；需要更可靠的断线电平时可在 DO 加约 10 kΩ 到 3.3 V 的外部上拉。

独立 core 0 编码器任务仍由 PWM 节拍以 2.5 kHz 唤醒，core 1 的 5 kHz 电流任务消费快照。SPI 和 ADC 分别申请 DMA 通道；SSI 传输等待不进入电流环。MT6701 的角度延迟补偿取 5 μs、分辨率为 16384 码/圈；AS5600 后端保留 150 μs 补偿及 4096 码/圈。

MT6701 必须通过 CRC 和磁场状态检查：Mg[1:0]=0 为正常，1/2 为磁场过强/过弱，3 为保留值也拒绝；Mg[3]=1 表示失去跟踪，停机。Mg[2] 是按压检测，不单独作为角度故障。`KNOB_ALLOW_WEAK_MAGNET` 只影响 AS5600，MT6701 不沿用旧磁铁的弱磁容忍。旧 AS5600 测量记录不能说明新编码器的磁场是否合格。

选择集中在 `components/knob_encoder/include/encoder_config.hpp` 的 `kind`，默认 `EncoderKind::mt6701`；改为 `EncoderKind::as5600` 可恢复 GPIO8/9 的原 I²C 后端，不需要额外编译参数。更换类型后配置保留，旧类型的校准失效，重新执行 `calibrate`，停机后 `save`。两种驱动都不烧写编码器 OTP/EEPROM。

## 2026-11-04 当前实验版：10 kHz / 50%，运行限制 3.0 V

最终已烧录 `dma-localized-v4-10k50-voltage-exp3`，PWM **10 kHz**，电流环 **5 kHz**，编码器 **2.5 kHz**。最大 duty 从40%逐步提高到 **50%**，公共低侧窗口保留 **50 μs**，三次名义 START 为 −15/0/+15 μs；没有实施70%方案。11.62 V配置母线下理论软件上限为 **3.0860527 V**；实际设备已验证3.0 V接受、3.1 V拒绝。

## 2026-11-03 AS5600 设备记录

本轮 Windows 设备为 COM7，原生 USB `303a:1001`，ESP32-S3 rev 0.2，MAC **1c:29:04:38:1e:b8**。Flash 0x0–0x10FFFF（启动、NVS 和应用）已在修改前读出备份；本轮仅烧录应用分区，随后显式保存验证后的调参结果。以下历史记录中的另一个 MAC 不能作为本轮板卡的身份。

ADC1 使用固定 9 项硬件扫描表和 GDMA，三次软件触发组成一次突发：第一个 DMA 字为先前转换结果，随后两字对应当前两相；尾部转换仅用于刷新流水线。START 在 DMA 回调中清零并保持至下个 PWM 事件，避免低电平过短而漏触发。扫描表在启动时配置，运行中不改写预加载的模拟多路选择器。

PWM 公共低侧窗口为 −15 至 +15 μs，采集开始必须晚于下降沿 6 μs，第二次转换完成须早于上升沿 1 μs。每四个 PWM 周期采样，控制目标 200 μs（5 kHz）；失效样本会被丢弃，持续 1.5 ms 的失效样本会停机。这里的时序是片上计数器和 ADC 状态核验，未使用示波器测量模拟建立时间。

当时 AS5600 使用 400 kHz I²C、独立 core 0 任务约 2.5 kHz 更新；单次三字节读取约 203 μs。电机控制任务在 core 1 上使用快照，避免串行等待占用电流环预算。低速校准电压/电流表明在当前感测换算下名义电阻约 4.5 Ω，用作前馈估计；此数值不能替代电阻计或正确 GAIN 下的物理参数测量。

## AS5600 历史磁铁和测量条件

AS5600 实测 STATUS=`0x33`，MD=1、ML=1、MH=0。用户确认机械间隙不能缩小，并要求先忽略磁场偏弱，因此原配置显式启用 `KNOB_ALLOW_WEAK_MAGNET`；该设置在保留的 AS5600 后端继续有效，不适用于默认 MT6701。状态判断只检查有效位，不把保留位当作故障；缺磁铁和过强磁场仍拒绝驱动。

旧版为 ISR 忙等两相 ADC 约 18–19 μs、控制周期 500 μs；当前为上述 GDMA / 200 μs 架构。GAIN 未经电阻/电压实测确认，遥测中的 A 按 0.15 V/A 计算，不能替代外部电流测量。当前校准确认了引脚对应的相序和编码器方向，仍未完成整个负载与转速范围的仪器验证。

此前恢复调试时枚举的是 WCH COM 桥（`1a86:55d3`），当时的结果仅覆盖 UART0；原生 USB 验证以本次 2026-10-30 记录为准。

转动测试发现的 `0x103` 同时也是 IDF 5.5 I²C 事务失败的返回值，不能单凭该码断言磁铁丢失。固件分别保留传输错误、磁铁状态和重试次数，并对预算内的短暂传输失败重试一次。此前曾降至 300 kHz，本轮独立任务使用 400 kHz，测试情况见当前联调记录。
